# ЛАБОРАТОРНАЯ РАБОТА №2
РАБОТА С ФАЙЛАМИ. СИНХРОННЫЙ, АСИНХРОННЫЙ ВВОД-ВЫВОД И ОТОБРАЖЕНИЕ ФАЙЛОВ В ПАМЯТЬ
1. Цель работы
Изучить средства операционной системы Windows для работы с файлами и организации ввода-вывода.

Получить практические навыки:

-      открытия, создания и закрытия файлов;

-      чтения и записи данных посредством Windows API;

-      работы с файловыми дескрипторами HANDLE;

-      выполнения синхронных операций ввода-вывода;

-      выполнения асинхронных операций ввода-вывода;

-      использования структуры OVERLAPPED;

-      ожидания завершения операций ввода-вывода;

-      отображения файлов в виртуальную память процесса;

-      обработки больших файлов;

-      организации прямого доступа к данным в файле;

-      контроля нескольких одновременно выполняемых операций ввода-вывода;

-      оценки производительности различных способов работы с файлами.

 

2. Теоретическая часть
Перед выполнением лабораторной работы необходимо изучить следующие вопросы.

2.1. Файлы и файловая система
Необходимо знать:

-      понятие файла;

-      понятие каталога;

-      абсолютные и относительные пути;

-      файловый объект Windows;

-      файловый дескриптор HANDLE;

-      права доступа к файлу;

-      режимы совместного использования файла;

-      создание и открытие файла;

-      файловый указатель;

-      размер файла;

-      завершение работы с файловым объектом.

Основные функции Windows API:

CreateFile()
CloseHandle()
GetFileSizeEx()
SetFilePointerEx()
SetEndOfFile()
FlushFileBuffers()

 

2.2. Синхронный ввод-вывод
При синхронной операции программа инициирует операцию чтения или записи и ожидает ее завершения.

Основные функции:

ReadFile()
WriteFile()

Необходимо понимать:

-      последовательное чтение;

-      чтение блоками;

-      запись блоками;

-      позиционирование внутри файла;

-      влияние размера блока на производительность.

 

2.3. Асинхронный ввод-вывод
Асинхронный ввод-вывод позволяет инициировать операцию и продолжить выполнение программы до ее завершения.

Файл открывается с флагом:

FILE_FLAG_OVERLAPPED.

Для каждой независимой операции используется структура:

OVERLAPPED.

Основные функции и объекты:

ReadFile()
WriteFile()
GetOverlappedResult()
WaitForSingleObject()
WaitForMultipleObjects()
CreateEvent()
ResetEvent()

Необходимо понимать:

-      начало асинхронной операции;

-      значение ERROR_IO_PENDING;

-      контроль завершения операции;

-      одновременное выполнение нескольких операций;

-      необходимость использования отдельной структуры OVERLAPPED для каждой незавершенной операции.

 

2.4. Отображение файла в память
Отображение файла позволяет работать с содержимым файла как с участком виртуальной памяти процесса.

Основные функции:

CreateFileMapping()
MapViewOfFile()
UnmapViewOfFile()
FlushViewOfFile()

Необходимо понимать:

-      объект отображения файла;

-      представление файла;

-      смещение отображения;

-      размер отображаемого участка;

-      отличие отображения файла от обычного ReadFile() / WriteFile();

-      возможность отображения частей большого файла.

 

2.5. Мультиплексирование операций ввода-вывода
Под мультиплексированием в данной лабораторной работе понимается возможность одной программы контролировать несколько одновременно выполняемых операций ввода-вывода.

Для асинхронных файловых операций рекомендуется использовать:

WaitForMultipleObjects()

с событиями, связанными со структурами OVERLAPPED.

Для сокетов допускается использование:

select().

Следует учитывать, что в Windows функция select() относится прежде всего к Winsock и не предназначена для обычного ожидания файловых HANDLE.

 

3. Общая постановка задачи
Разработать приложение для Windows согласно индивидуальному варианту.

Приложение может быть:

-      консольным;

-      оконным.

Основные операции с файлами должны выполняться средствами Windows API.

Допускается использование стандартной библиотеки языка для:

-      формирования тестовых данных;

-      обработки строк;

-      вычислений;

-      отображения результатов.

Однако непосредственное чтение, запись и отображение исследуемых файлов должны выполняться посредством соответствующих механизмов Windows API.

 

4. Общие обязательные требования
Независимо от варианта программа должна:

Позволять пользователю указать входной файл либо создавать тестовый файл заданного размера.
Проверять существование файлов и корректность параметров.
Корректно обрабатывать ошибки Windows API.
При ошибке необходимо вывести:

-      название операции;

-      код GetLastError();

-      текстовое описание ошибки.

Корректно освобождать все созданные системные ресурсы:
-      файловые дескрипторы;

-      события;

-      объекты отображения;

-      отображенные представления.

Измерять время выполнения исследуемых операций.
Для измерения рекомендуется использовать:

QueryPerformanceCounter().

Проверять корректность полученного результата.
Не использовать файлы критически важных данных пользователя.
Для экспериментов рекомендуется генерировать отдельные тестовые файлы.

 

5. Требования к исследованию производительности
Для вариантов, предусматривающих сравнение способов ввода-вывода, необходимо выполнить эксперимент минимум для трех размеров файла.

Рекомендуемые размеры:

-      10 МБ;

-      100 МБ;

-      500 МБ.

При наличии достаточного объема оперативной памяти и дискового пространства допускается использовать большие файлы.

Для операций с размером блока исследовать, например:

-      4 КБ;

-      64 КБ;

-      1 МБ;

-      4 МБ.

Каждый эксперимент выполнить не менее трех раз.

В отчет занести среднее или медианное время.

Необходимо учитывать, что операционная система использует файловое кэширование, поэтому результаты последовательных запусков могут отличаться.

# Вариант 26. Файловая база переменного размера

Реализовать хранение записей, содержащих строки переменной длины.

Пример:

-      ID;

-      длина текста;

-      текст.

Файл должен содержать небольшую служебную область с метаданными.

Реализовать:

-      добавление;

-      последовательный просмотр;

-      поиск по ID.

В отчете объяснить, почему прямой доступ к переменным записям сложнее, чем к записям фиксированной длины.
