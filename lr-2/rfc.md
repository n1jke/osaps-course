# RFC: лабораторная №2, вариант 26

Основание: [README.md](README.md). Лимит RFC — 8 000 символов. Реализация — в `src`; ручная проверка — позднее на Windows.

## 1. Цель и интерфейс

Консольная база переменных строк: создание, добавление, просмотр, поиск по UUID. C++17, Windows x64, CMake как lr-1, синхронный WinAPI. Async, mapping, индекс, удаление/изменение не реализуем.

```text
main.exe create <file>
main.exe add <file> "<text>"
main.exe list <file>ММ
main.exe find <file> <uuid>
main.exe --help
```

UUID создаёт программа; пользователь использует его в `find`. УVМникальность не проверяем. `check` отсутствует; `generate` описан в разделе 7. Путь базы задаёт пользователь.

Коды: `0` — успех/«не найдено», `1` — ошибка выполнения/формата, `2` — аргументы. Текст может быть пустым; пробелы — в кавычках. UUID: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`, hex без учёта регистра.

## 2. Файлы и три namespace

| Файл / namespace | Ответственность |
| --- | --- |
| `src/main.cpp` | Координация команд, вывод результата/времени, код выхода |
| `src/cli.h`, `src/cli.cpp` / `cli` | Аргументы и справка через `std` |
| `src/codec.h`, `src/codec.cpp` / `codec` | `Record`, сериализация, ASCII, форматирование через `std`; без HANDLE/I/O |
| `src/file_io.h`, `src/file_io.cpp` / `file_io` | Файловые операции, обход, ошибки, UUID и таймер через WinAPI |
| `CMakeLists.txt` | Один executable, C++17, Windows-only, `kernel32` и `rpcrt4` |

Codec: `serialize(record)` → байты, `deserialize(bytes)` → запись/ошибка; длина полной записи проверяется. Вывод форматирует codec, преобразования UUID — file_io. Объявления — `.h`, реализации — `.cpp`.

Зависимости: `main` → три модуля; `file_io` → `codec`. Свои классы не нужны; HANDLE закрывает std::unique_ptr.

Вход — `main`, аргументы/пути — `std::string`, текст/пути только ASCII. Unicode и преобразований кодировок нет. Вспомогательные функции — в трёх именованных namespace, анонимных нет.

## 3. Формат файла

| Область | Поля |
| --- | --- |
| Заголовок, 12 байт | `version: uint32`, `record_count: uint64` |
| Запись, 20 + N байт | `uuid: 16 байт`, `text_length: uint32`, `text: N байт ASCII` |

Размер берётся через `GetFileSizeEx`; сигнатуры нет. Заголовок фиксированный, база растёт. Пустая база — 12 байт, версия 1, count=0; нулевой файл отклоняется.

Числа — little-endian. UUID — байты канонической строки; поля Windows GUID переводятся в этот порядок явно. C++-структуры целиком не записывать из-за padding. Текст без завершающего нуля; длина в байтах. Максимум — 1 MiB.

Перед выделением буфера проверять длину, лимит, оставшиеся байты и переполнение. Смещения/размеры — 64-битные; запрос WinAPI укладывается в DWORD. Файл не загружается целиком: один буфер записи. Общий обход проверяет версию, границы, ASCII, количество записей и точное достижение EOF. UUID не проверяется на уникальность; при совпадении `find` возвращает первую запись. Без сигнатуры случайный файл теоретически может удовлетворить формату; без checksum не выявляется любая порча текста.

## 4. Файловые операции и ошибки

- `create`: `CreateFileA(..., CREATE_NEW, ...)`, записать заголовок, сбросить, перечитать и сравнить. Существующий файл не перезаписывать.
- `open`: `OPEN_EXISTING`; проверять успех и что открыт обычный файл, а не каталог. Читающим командам разрешить только совместное чтение; добавление открывает базу на чтение/запись без sharing.
- `read_exact` / `write_all`: `ReadFile` / `WriteFile`, учитывать фактические байты и повторять неполный запрос. Преждевременный EOF и нулевой прогресс записи — ошибка.
- `seek` / `size` / `save`: `SetFilePointerEx`, `GetFileSizeEx`, `FlushFileBuffers`. Закрытие — `CloseHandle`, включая ошибки и ранний выход.
- UUID: [UuidCreate](https://learn.microsoft.com/en-us/windows/win32/api/rpcdce/nf-rpcdce-uuidcreate), `rpc.h`, `rpcrt4`. Разбор/вывод — UuidFromStringA/UuidToStringA, освобождение строки — RpcStringFreeA. Ошибки — RPC_STATUS.
- Диагностика: скопировать `printWinError(operation, error)` из [worker.cpp](../lr-1/src/worker.cpp). Код I/O брать через `GetLastError()` до очистки. Выводить операцию, код и текст `FormatMessage`; при сбое форматирования — код. Для UUID передавать RPC_STATUS, для неверных данных — своё сообщение.

### Добавление

Проверить базу без поиска дубликатов, создать UUID, сериализовать текст. Запомнить count/размер, дописать запись, сбросить; обновить count, сбросить. Перечитать запись/count и сравнить с ожидаемыми; затем вывести успех/UUID.

При сбое попытаться вернуть старый count/размер через `SetFilePointerEx`/`SetEndOfFile`, сбросить; сообщить результат отката. Заранее повреждённую базу не исправлять. Журнала нет: авария/отключение питания может повредить файл, атомарность не гарантируется.

### Просмотр и поиск

Обход: прочитать 20-байтовый заголовок и текст, десериализовать. List выводит по порядку, find возвращает первое совпадение/«не найдено» после полного обхода. При ошибке list возможен частичный вывод. Поиск/проверка перед вставкой линейны по объёму.

## 5. Общие требования и ограничения

Раздел 4 README: проверять путь/параметры, диагностировать WinAPI, закрывать HANDLE, измерять время и проверять результат. Событий/mapping нет. Файловый I/O через `fstream`/`FILE*` запрещён; `std` — обработка и вывод.

Таймер — `QueryPerformanceCounter`/`QueryPerformanceFrequency`; выводить мс и объём обработки. Границы add/find — в разделе 7; list измеряет чтение/разбор без печати.

Только учебные базы. Командная строка Windows короче лимита текста. Конкурентная запись запрещена sharing. Тесты не писать; на macOS ничего не собирать/запускать.

## 6. Этапы и последующая ручная проверка

1. CLI, модели и codec: справка, разбор UUID, round-trip записи, пустой/ASCII-текст.
2. WinAPI-обёртки, ошибки и create: новая база 12 байт, повторное создание — отказ без перезаписи.
3. Добавление/обход: UUID выдаётся программой; три текста `A`, `Hello`, пустая строка дают count=3 и размер `12 + 21 + 25 + 20 = 78` байт.
4. List/find, встроенные проверки и время: найти выданный UUID после повторного открытия, неизвестный UUID → «не найдено», неправильный UUID → ошибка аргумента.
5. CMake и инструкция: собрать Release x64 на Windows по образцу lr-1. Проверить пробелы в ASCII-путях и отказ для не-ASCII, запрет доступа, отсутствие файла, усечённую запись, неверные version/count/длину на копиях, освобождение HANDLE и ошибку записи/откат.

Проверять вручную, фиксировать результат/код выхода. В отчёте объяснить кэш и прямой доступ: фиксированные записи адресуются по номеру, переменные требуют длин предыдущих либо индекса UUID → смещение. UUID не равен номеру.

## 7. Генератор и замеры поиска/вставки

`main.exe generate <file> <count> <maxLen>` создаёт count записей. Count — положительный uint64, maxLen — 1..1048576 **байт**. До создания проверить аргументы/переполнение `12 + count × (20 + maxLen)`; существующий файл не перезаписывать.

Длины — равномерно 1..maxLen через `std::mt19937`/`uniform_int_distribution`, текст — случайные ASCII-буквы. UUID генерируются без проверки уникальности. Main готовит данные через std, codec кодирует, file_io пишет последовательно без add/повторных обходов. Каждую запись перечитать и сравнить побайтово; затем сохранить count, сбросить, проверить структуру/размер. Хеширования нет. Память — одна запись; при сбое сообщить о неполном файле.

Вывести count, размер, UUID первой/средней/последней записи. Add/find выводят `elapsed_ms`, включая «не найдено». Add измеряет проверку базы, запись/сбросы; исключает UUID/сериализацию и финальное перечитывание. Find измеряет полный обход с валидацией. Открытие/печать исключены.

Ручной эксперимент: generate на 10/100/1000 записей с одинаковым maxLen; по три поиска выбранных UUID и отсутствующего ID. Для трёх вставок — свежие копии одной базы. В таблице: count, фактический размер, maxLen, операция, три времени и медиана. Проверить count=0/maxLen=0/переполнение, случай maxLen=1 и точный размер `12 + count × 21`. Код тестов не писать.
