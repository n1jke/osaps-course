# Лабораторная № 6. Ответы на контрольные вопросы

Нумерация соответствует [разделу 15 задания](readme.md).

## Реестр Windows

1. **Что такое реестр Windows?** Это иерархическое хранилище настроек Windows, оборудования, пользователей и приложений. [Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry)
2. **Как организована структура реестра?** От корневых разделов идут подразделы. Например, `HKEY_LOCAL_MACHINE` содержит настройки компьютера, а `HKEY_CURRENT_USER` — настройки текущего пользователя. В каждом разделе могут быть подразделы и значения.
3. **Что такое раздел и значение реестра?** Раздел (`key`) — узел дерева. Значение (`value`) — запись внутри раздела. У неё есть имя, тип и данные. У значения по умолчанию имя пустое.
4. **Чем REG_SZ отличается от REG_EXPAND_SZ?** `REG_SZ` хранит обычную строку. `REG_EXPAND_SZ` может содержать ссылки на переменные окружения, например `%SystemRoot%`. При необходимости приложение раскрывает их через `ExpandEnvironmentStrings`. [Типы значений](https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry-value-types)
5. **Для чего используется REG_DWORD?** Для 32-битного числа, например флага настройки или счётчика.
6. **Для чего используется REG_BINARY?** Для последовательности байтов. Формат этих байтов определяет приложение, которое их записывает.
7. **Как перечислить подразделы реестра?** Открыть нужный раздел через `RegOpenKeyEx` с правом `KEY_ENUMERATE_SUB_KEYS`, затем вызывать `RegEnumKeyEx` с индексами от нуля до `ERROR_NO_MORE_ITEMS`. Открытый дескриптор закрывается через `RegCloseKey`. [Функции реестра](https://learn.microsoft.com/en-us/windows/win32/sysinfo/registry-functions)
8. **Для чего применяется RegQueryValueEx()?** Чтобы прочитать данные именованного значения из открытого раздела. Вызов также позволяет получить тип и требуемый размер буфера.
9. **Как определить тип значения реестра?** Передать адрес переменной `DWORD` в параметр `lpType` функции `RegQueryValueEx`. После успеха там будет константа типа, например `REG_DWORD`.
10. **Что такое дескриптор раздела реестра?** `HKEY` — значение, через которое WinAPI обращается к открытому разделу с правами, полученными при открытии. Корневые разделы представлены предопределёнными `HKEY`.
11. **Как контролировать изменения реестра?** Открыть нужную ветку, подписаться на уведомления и после сигнала перечитать интересующие данные. Сравнение с предыдущим снимком показывает, что изменилось.
12. **Для чего используется RegNotifyChangeKeyValue()?** Сообщает об изменениях раздела или его поддерева по выбранному фильтру. В асинхронном режиме функция сигнализирует объект события. После получения уведомления вызов повторяют, чтобы ждать следующего. [Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regnotifychangekeyvalue)
13. **Почему уведомление об изменении не содержит полного описания изменения?** API сообщает о факте изменения в области наблюдения. Сигнал не содержит имени изменённого значения или пары старых и новых данных. Детали определяет приложение при повторном чтении.
14. **Как реализовать сравнение двух снимков реестра?** Сопоставить записи по пути раздела и имени значения. Записи только в новом снимке считаются добавленными, только в старом — удалёнными. Для совпавших записей сравниваются тип и данные.
15. **Почему нельзя удалять произвольные записи реестра?** Ими могут пользоваться Windows, службы или другие программы. Удаление может нарушить их работу. В лабораторной для таких операций выделена отдельная учебная ветка.
16. **Для чего необходимо предварительное сохранение изменяемых данных?** Чтобы восстановить исходное состояние при ошибке. Для отдельного значения сохраняют имя, тип, данные и факт его существования до изменения.

## Системная информация

17. **Как получить сведения о процессоре?** `GetNativeSystemInfo` возвращает архитектуру и число логических процессоров в текущей группе. Модель процессора можно получить через WMI из свойства `Name` класса `Win32_Processor`. [GetNativeSystemInfo](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getnativesysteminfo)
18. **Как определить объём оперативной памяти?** Заполнить `MEMORYSTATUSEX`, указав её размер, и вызвать `GlobalMemoryStatusEx`. `ullTotalPhys` содержит объём физической памяти в байтах, `ullAvailPhys` — объём доступной в момент вызова. [GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)
19. **Как получить сведения о логических дисках?** `GetLogicalDriveStrings` перечисляет корневые пути дисков. Для каждого `GetDriveType` определяет тип, а `GetDiskFreeSpaceEx` возвращает сведения о ёмкости и свободном месте. [Функции управления томами](https://learn.microsoft.com/en-us/windows/win32/fileio/volume-management-functions)
20. **Что такое WMI?** Windows Management Instrumentation — инфраструктура для получения сведений о системе и управления её компонентами. Например, запрос к классу `Win32_Processor` возвращает свойства процессора. [Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/wmisdk/wmi-start-page)

## Журнал событий Windows

21. **Что такое журнал событий Windows?** Система хранит в нём структурированные события от Windows и приложений. В записи обычно есть время, поставщик, идентификатор события и уровень. События можно посмотреть в Event Viewer. [Windows Event Log](https://learn.microsoft.com/en-us/windows/win32/wes/windows-event-log)
22. **Какие журналы Windows существуют?** Основные журналы в разделе Windows Logs — `Application`, `Security`, `Setup`, `System` и `Forwarded Events`. У служб и приложений также бывают отдельные каналы.
23. **Что такое источник события?** Это имя приложения или компонента, записавшего событие. В классическом API используется источник событий, в современном Windows Event Log — поставщик (`provider`).
24. **Чем событие Warning отличается от Error?** `Warning` обозначает потенциальную проблему или нежелательное состояние. `Error` фиксирует сбой операции или компонента. Уровень выбирает источник события.
25. **Для чего используется EvtQuery()?** Создаёт запрос к каналу или сохранённому журналу. Фильтр XPath или структурированный XML-запрос позволяет выбрать нужные события. [EvtQuery](https://learn.microsoft.com/en-us/windows/win32/api/winevt/nf-winevt-evtquery)
26. **Как получить данные выбранного события?** Получить дескриптор события через `EvtNext`, затем вызвать `EvtRender`, чтобы прочитать XML или отдельные свойства. Дескрипторы событий и запроса освобождаются через `EvtClose`. [EvtRender](https://learn.microsoft.com/en-us/windows/win32/api/winevt/nf-winevt-evtrender)
27. **Для чего используется ReportEvent()?** Записывает событие через классический Event Logging API. Функции передают дескриптор источника, тип, идентификатор и дополнительные данные события. [ReportEventW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-reporteventw)

## Оконные сообщения и WinHook

28. **Что такое оконное сообщение Windows?** Уведомление или команда для окна. Код сообщения задаёт его смысл, а `wParam` и `lParam` передают данные, зависящие от типа. Например, у `WM_TIMER` параметр `wParam` содержит идентификатор таймера. [Сообщения и очереди](https://learn.microsoft.com/en-us/windows/win32/winmsg/about-messages-and-message-queues)
29. **Чем SendMessage() отличается от PostMessage()?** `SendMessage` передаёт сообщение оконной процедуре синхронно и ждёт результата обработки. `PostMessage` помещает сообщение в очередь потока-владельца окна и возвращается до обработки.
30. **Что такое очередь сообщений?** Это очередь, связанная с потоком. Она обслуживает окна этого потока. Цикл сообщений получает очередное сообщение через `GetMessage` и обычно передаёт его оконной процедуре через `DispatchMessage`.
31. **Что такое WinHook?** Механизм, через который Windows вызывает установленную приложением функцию при обработке определённых событий. Тип перехватчика задаёт, какие события наблюдаются. В варианте 26 перехватчик ограничен собственным GUI-потоком. [Механизм Hooks](https://learn.microsoft.com/en-us/windows/win32/winmsg/about-hooks)
32. **Для чего используется SetWindowsHookEx()?** Устанавливает функцию обратного вызова в цепочку перехватчиков. В нашей работе указываются `WH_GETMESSAGE`, адрес обработчика и идентификатор собственного GUI-потока. Возвращённый `HHOOK` нужен для снятия перехватчика.
33. **Для чего необходимо вызывать CallNextHookEx()?** Чтобы следующее звено цепочки получило то же событие. Для `WH_GETMESSAGE` при отрицательном коде обработчик обязан сразу передать управление дальше и вернуть результат `CallNextHookEx`. [GetMsgProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/getmsgproc)
34. **Как удалить установленный перехватчик?** Вызвать `UnhookWindowsHookEx` с дескриптором `HHOOK`, полученным при установке, и проверить возвращённое значение.
35. **Чем WH_GETMESSAGE отличается от WH_CALLWNDPROC?** `WH_GETMESSAGE` наблюдает сообщения, которые `GetMessage` или `PeekMessage` возвращают из очереди. `WH_CALLWNDPROC` наблюдает отправляемые сообщения перед их передачей оконной процедуре, например при `SendMessage`. В варианте 26 единица учёта — извлечение сообщения с `PM_REMOVE`.

## DLL и смешанные сборки

36. **Что такое DLL?** Динамически подключаемая библиотека Windows. Она может содержать функции, данные и ресурсы, которыми пользуются исполняемые модули. [Динамические библиотеки](https://learn.microsoft.com/en-us/windows/win32/dlls/about-dynamic-link-libraries)
37. **Чем динамическая библиотека отличается от статической?** Код из статической библиотеки включается в итоговый исполняемый модуль при компоновке. DLL остаётся отдельным модулем и загружается при запуске или во время работы.
38. **Что такое экспортируемая функция?** Функция DLL, доступная другим модулям через таблицу экспорта по имени или порядковому номеру. В MSVC её можно объявить через `__declspec(dllexport)`.
39. **Чем явное связывание отличается от неявного?** При явном связывании приложение загружает DLL через `LoadLibrary` и получает адрес функции через `GetProcAddress`. При неявном связывании линковщик использует импортную библиотеку, а загрузчик разрешает импорты при запуске процесса или загрузке модуля.
40. **Для чего используется LoadLibrary()?** Загружает DLL в адресное пространство текущего процесса и возвращает дескриптор `HMODULE`. При сбое возвращает `NULL`.
41. **Для чего используется GetProcAddress()?** Получает адрес экспортированной функции или переменной по имени или порядковому номеру. Адрес вызываемой функции приводят к указателю с подходящей сигнатурой и соглашением о вызове.
42. **Для чего используется FreeLibrary()?** Уменьшает счётчик ссылок на загруженный модуль. Если счётчик достигает нуля, DLL выгружается. После этого сохранённые указатели на её функции использовать нельзя. [FreeLibrary](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-freelibrary)
43. **Что произойдёт, если DLL отсутствует?** Если библиотека нужна при обычном запуске по импорту, загрузчик не сможет запустить приложение. При явной загрузке `LoadLibrary` вернёт `NULL`, и программа сможет обработать сбой.
44. **Что такое соглашение о вызове?** Это правила передачи аргументов, возврата результата, использования регистров и работы со стеком. Например, на x86 соглашения `__cdecl` и `__stdcall` различаются тем, кто очищает стек после вызова.
45. **Почему важно обеспечивать совместимость интерфейсов DLL?** Приложение и библиотека должны одинаково понимать формат аргументов, возвращаемые значения и структуры. Нарушение двоичной совместимости может вызвать неверные результаты, повреждение памяти или аварийное завершение.
46. **Что такое смешанная сборка?** Сборка, содержащая управляемый код для CLR и нативный машинный код. В C++/CLI такую сборку можно создать с параметром `/clr`. [Смешанные сборки C++](https://learn.microsoft.com/en-us/cpp/dotnet/mixed-native-and-managed-assemblies)
47. **Как взаимодействуют управляемый и нативный код?** Управляемый код может вызвать экспорт DLL через P/Invoke, либо код на C++/CLI может служить обёрткой для нативного API. На границе важно явно определить преобразование строк и структур, а также владельца памяти и ресурсов.

## Обработка ошибок и Git

48. **Почему необходимо проверять результаты Windows API?** У каждой функции свой способ сообщить об ошибке. Если продолжить работу после сбоя, приложение может передать неверный дескриптор, использовать неполные данные или оставить ресурс открытым. Например, в нашей работе `GetMessage` различает полученное сообщение, `WM_QUIT` и ошибку.
49. **Для чего используется GetLastError()?** Возвращает последний код ошибки текущего потока. Его считывают сразу после неудачного вызова, если это предусмотрено документацией функции. Если API возвращает код напрямую, как `RegQueryValueEx`, используют этот код. [GetLastError](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-getlasterror)
50. **Как система контроля версий Git помогает анализировать развитие программного проекта?** Коммиты фиксируют состояние проекта и позволяют связать изменение с автором и задачей. `git log` показывает историю, `git show` раскрывает один коммит, а `git diff` помогает сравнить версии. Для лабораторной хеш позволяет указать версию программы, на которой выполнены замеры. [Документация Git](https://git-scm.com/docs/git-log)

| **Реестр Windows (1–16)** | Теория. Вариант посвящён оконным сообщениям. Частота, длительность и путь CSV передаются аргументами запуска, поэтому приложение не хранит свои настройки в реестре. |

| **Оконные сообщения и WinHook (28–35)** | Это основа варианта. `SetWindowsHookEx` устанавливает `WH_GETMESSAGE` на собственный GUI-поток. | **DLL и смешанные сборки (36–47)** | Собственной DLL и C++/CLI в работе нет. Исходники разделены на `options` для аргументов, `main` для окна и цикла сообщений, `monitor` для замера и `output` для файлов и диагностики. Системные библиотеки указаны в CMake и подключаются через импорт при компоновке. |
| **Обработка ошибок и Git (48–50)** | Например, `GetMessage` проверяется на `-1`, а при неудачном `SetWindowsHookEx` программа сразу сохраняет `GetLastError`. Диагностика показывается в окне и пишется в журнал. В Git отдельно зафиксированы код замера, полученные CSV и обработка результатов. |
