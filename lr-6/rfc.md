# RFC — ЛР №6, вариант 26. Анализ интенсивности оконных сообщений

Статус — согласован, реализация подготовлена. Проверка на Windows ожидается.

## Цель и границы

Оконное приложение Windows измеряет, какие сообщения получает GUI-поток и сколько сообщений каждого типа приходит за секунду. Учебный таймер создаёт периодические `WM_TIMER`, чтобы сравнить интенсивность в трёх режимах даже без действий пользователя.

Один процесс, один GUI-поток, C++17 и CMake. `WH_GETMESSAGE` действует только на текущий поток приложения. На диск сохраняются агрегаты и журнал основных действий.

## Интерфейс и ход работы

```text
lr6.exe [--hz 10|50|100] [--seconds 1..300] [--csv PATH]
```

По умолчанию — 10 срабатываний/с, 30 секунд и `test_<run_id>.csv` в рабочем каталоге. Настройки фиксируются на весь запуск приложения. Ширина интервала — 1 секунда. Явный путь должен вести в существующую папку. Для следующего прогона с явным путём используй новое имя или перенеси предыдущий CSV.

| Кнопка | Действие |
|---|---|
| Старт | Создаёт новый `RUN_ID`, подготавливает счётчики, устанавливает перехватчик и запускает таймеры. Во время замера отключена. |
| Стоп | Завершает текущий замер досрочно и показывает результаты. |
| Тест | Во время замера отправляет 10 сообщений одного учебного типа `WM_APP + 1` в главное окно через `PostMessage` и обновляет надпись с числом успешных отправок. |

Окно показывает состояние прогона, итоговое число сообщений, число срабатываний учебного таймера и фактическую частоту. При ошибке запуска отображается синтаксис команды. Коды завершения — `0` при штатном выходе, `1` при фатальной ошибке и `2` при неверных аргументах.

`RUN_ID` различает прогоны в CSV и журнале. Для индивидуального эксперимента используется отдельно описанный сценарий действий пользователя. Случайного генератора в базовом сценарии нет.

## Данные и алгоритм

**Зарегистрированное сообщение** — одно наблюдение `HC_ACTION` с `PM_REMOVE` для `HWND` главного окна или его дочернего элемента в пределах замера. Считается код `MSG.message`. Исключаем служебные `WM_TIMER`, просмотры с `PM_NOREMOVE` и сообщения без `HWND`. Прямые вызовы оконных процедур через `SendMessage` проходят мимо перехватчика. Поэтому число кликов и число сообщений могут различаться.

**Срабатывание таймера** — зарегистрированное `WM_TIMER` с `MSG.hwnd`, равным главному окну, и `MSG.wParam`, равным ID учебного таймера текущего прогона. Это событие входит и в общий счётчик `WM_TIMER`, и в отдельный счётчик учебного таймера. Одно событие увеличивает общий итог сообщений ровно на единицу.

- После запуска учебного таймера фиксируем `t0` через `QueryPerformanceCounter`. Учёт включается после успешного запуска служебного таймера. Для полного прогона конец равен `t0 + длительность`, для досрочного — более ранней отметке команды «Стоп» или закрытия окна. Событие учитывается, если его отметка при вызове перехватчика лежит в `[t0, конец)`.
- Интервал определяется целой частью числа секунд от `t0`. Досрочный прогон может иметь последний неполный интервал. Время окончания и ширину последнего интервала сохраняем по фактической границе учёта.
- Перехватчик обновляет заранее подготовленные счётчики в памяти. В нём отсутствуют файловый ввод-вывод, обновление элементов окна и выделение памяти. Все операции со счётчиками выполняет GUI-поток. Для кодов 0…65535 выделяется по 4 байта на код и интервал, до 75 МиБ на прогон.
- Заданная частота равна `1000 / период_мс`. Фактическая частота учебного таймера равна числу его `WM_TIMER`, делённому на длительность учтённого интервала в секундах. Общую интенсивность считаем по всем зарегистрированным сообщениям.

### CSV

После остановки пригодный результат автоматически сохраняется в `test_<timestamp>.csv` в рабочем каталоге. Имя содержит `RUN_ID`, сформированный из UTC FILETIME при запуске прогона. Один UTF-8 CSV на прогон, разделитель — запятая, дробная часть отделяется точкой. Одна строка на интервал и наблюдавшийся в нём тип сообщения. Для пустого интервала сохраняется строка с пустым `message_id` и нулевыми счётчиками.

```text
run_id,target_hz,period_ms,requested_ms,observed_ms,status,interval_start_ms,interval_end_ms,message_id,count,study_timer_count
```

Границы интервала указаны относительно `t0`, `message_id` — десятичный код `MSG.message`. `study_timer_count` выделяет учебный таймер внутри строки `WM_TIMER`, для прочих типов равно нулю. `status` принимает `completed` или `stopped`. Ошибочный прогон диагностируется и исключается из сравнения. Сохранение показывает путь и результат, при ошибке сохранения окно показывает диагностику.

## WinAPI, ошибки и ресурсы

- Цикл получает сообщения через `GetMessage` без фильтра. Положительный результат обрабатывается через `TranslateMessage` и `DispatchMessage`, `0` завершает цикл после `WM_QUIT`, `-1` считается ошибкой. Оконная процедура обрабатывает кнопки и таймеры, прочие сообщения передаёт в `DefWindowProc`.
- `SetWindowsHookEx(WH_GETMESSAGE, …, nullptr, GetCurrentThreadId())` устанавливает перехватчик перед замером. При отрицательном коде управление сразу передаётся в `CallNextHookEx`. Для остальных кодов перехватчик завершает работу тем же вызовом и возвращает его результат, оставляя исходное сообщение без изменений.
- `SetTimer` для главного окна с `lpTimerFunc = nullptr` задаёт учебный период 100, 20 или 10 мс. Отдельный оконный таймер с собственным ID будит цикл для завершения прогона. Его сообщения исключаются из агрегатов. После каждого успешного `GetMessage` цикл проверяет дедлайн, поэтому при активном вводе завершение не ждёт служебного `WM_TIMER`. Оконная процедура также проверяет дедлайн при получении `WM_TIMER`, в том числе при перемещении окна. Если UI обработает дедлайн позже, границу учёта всё равно определяет `QueryPerformanceCounter`.
- При остановке, закрытии окна или ошибке запуска сначала прекращаем учёт, затем снимаем перехватчик через `UnhookWindowsHookEx` и удаляем созданные таймеры через `KillTimer`. При ошибке освобождения новый прогон блокируется, сбой отображается в окне и журнале. Следующий прогон получает новые ID таймеров. Поздние уведомления от предыдущего прогона исключаются из учёта.
- Проверяем существенные вызовы WinAPI по их контрактам. Если API документирует `GetLastError`, сохраняем код сразу после ошибки и расшифровываем через `FormatMessage`. В журнал пишем время, операцию, объект, результат и код ошибки при наличии. Журнал `lr6.log` создаётся в рабочем каталоге. Старт, каждое нажатие «Тест», ошибки активного прогона, остановка и экспорт получают отметку времени события и накапливаются в векторе. Записи сбрасываются в журнал после остановки. CSV сначала записывается во временный файл в той же папке и переносится в целевой путь после успешного закрытия. Автоматическое сохранение защищает существующий файл от замены.

## Структура реализации

| Файл или модуль | Ответственность |
|---|---|
| `src/options.h` / `.cpp` | Параметры запуска и проверка аргументов |
| `src/main.cpp` | Создание окна, элементы управления, цикл сообщений и координация прогона |
| `src/monitor.h` / `.cpp` | Таймеры, перехватчик, границы замера и счётчики |

| `CMakeLists.txt`, `USAGE.md` | Windows-сборка и сценарии проверки |

## Проверки и эксперименты

1. Выполнить Windows-сборку и проверить старт, автоматическое и ручное завершение, повторный запуск, экспорт и закрытие окна во время замера. Проверить ошибку сохранения и запустить приложение с доступным путём.
2. Во время замера нажать «Тест» с запасом до окончания. Сверить число успешных отправок с суммой `count` для `WM_APP + 1`. Сверить суммы по интервалам и типам со сводкой окна. Сумма `study_timer_count` должна совпадать с итогом учебного таймера и быть не больше суммы `count` для `WM_TIMER`.
3. На одном ноутбуке сравнить 10, 50 и 100 срабатываний/с при одинаковой длительности. Выполнить не менее трёх полных прогонов на режим без действий после старта. Сравнить общее число сообщений, число `WM_TIMER` учебного таймера, фактическую частоту и время выгрузки CSV.
4. В отдельном прогоне нажимать «Тест» и перемещать окно. Проверить обновление надписи, перерисовку и реакцию на «Стоп». Сравнить распределение по типам с базовым прогоном. Для графиков использовать фактические CSV и журнал времени экспорта.

## Решения

- Параметры по умолчанию — 30 секунд на прогон и интервалы по 1 секунде. Для графика времени измеряем полную выгрузку CSV, поскольку длительность базового замера задаётся заранее. Второй график показывает фактическую частоту учебного таймера.
- Индивидуальный сценарий и визуальная проверка отзывчивости описаны в `USAGE.md`.
